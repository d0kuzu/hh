# HH Auto Apply

Python + Selenium: поиск вакансий, персональные сопроводительные письма через LLM и пошаговый отчёт в Telegram. По умолчанию создаёт **5 писем без отправки откликов**. Для реальной отправки нужен `--apply`.

## Настройка для Наргиз

Профиль заполнен в `hh_auto_apply/user_profile.py`:

- Найзабекова Наргиз Рустемовна, 19 лет, Астана.
- Более года опыта: CoffeeBoom, август 2025 — март 2026; TomYumBar, март — сентябрь 2026.
- Бармен в TomYumBar: напитки по техкартам, настройка оборудования, экстракция эспрессо, чистка и дезинфекция, инвентаризация, сезонное меню и сервис.
- Бариста в CoffeeBoom: работа на потоке, настройка помола, консультирование гостей, касса и отчётность, приёмка и хранение сырья.
- Семь навыков продвинутого уровня, указанных в резюме: приготовление кофе и коктейлей, барное оборудование, настройка помола, обслуживание кофемашины, работа с кофемолкой/кофемашиной и работа в команде.
- Обязанности дополнены по предоставленному резюме. Измеримые достижения не добавлены; периоды не суммируются как 15 непересекающихся месяцев, поскольку март указан в обоих местах работы.
- Ориентир: **18 000 KZT за смену**, предпочтительно **2/2 или 5/2**, желательно **левый берег**.

Текущая настройка: `hh.kz`, Астана (`area=159`), два отдельных запроса «бармен» и «бариста» в названии. `HH_QUERIES=бармен,бариста` задаёт список запросов; если он пуст, используется одиночный `HH_QUERY`. Результаты объединяются по ID, повторяющиеся вакансии обрабатываются один раз. После конца выдачи первого запроса скрипт переходит ко второму. Поддерживается и `hh.ru`. Смена профессии требует изменения профиля и запросов, код менять не нужно.

### Как оцениваются условия

Предпочтения мягкие: график 6/1, другой график, правый берег и упоминание вахты/переезда получают **⚠️** в отчёте, но не исключают вакансию. При нескольких графиках показываются как подходящие, так и менее желательные варианты. Неизвестные условия отмечаются **🔎**. Эти пометки видны в логах после чтения вакансии, включая события с готовым письмом.

Оплата сравнивается по сумме из шапки вакансии. Для месячной оплаты нужен один распознанный график. При допущении «30 дней в месяце и одна смена в рабочий день» ориентиры следующие:

| График | Примерное число смен | Эквивалент 18 000 ₸/смена |
|---|---:|---:|
| 2/2 | 15 | 270 000 ₸/месяц |
| 5/2 | 21,4 | 385 714 ₸/месяц |
| 6/1 | 25,7 | 462 857 ₸/месяц |

Это ориентировочное сравнение: календарь, длительность смен, чаевые, премии и налоги нужно уточнять. Если диапазон пересекает ориентир, дополнительная пометка не выводится. Общая оговорка о сравнении остаётся здесь, а не повторяется в каждой карточке Telegram.

Берег определяется **только по явному упоминанию** в тексте/адресе. По одному названию улицы берег не угадывается; если берег неизвестен, отдельная пометка не выводится. Отчёт содержит адрес. Жёсткого географического фильтра по берегу нет. Город поиска задан параметром `HH_AREAS`; вакансии с переездом могут попадать в выдачу Астаны. Для поиска в других городах расширьте этот список.

## Быстрый запуск в Windows PowerShell

Нужен Python 3.11+ и Chrome. Selenium Manager подбирает драйвер; при отсутствии Chrome может скачать Chrome for Testing. Это требует сети. Можно указать путь к браузеру через `CHROME_BINARY`.

Если Selenium Manager не может скачать драйвер, задайте `CHROMEDRIVER_PATH` вместе с `CHROME_BINARY`. Используйте совместимые версии из [официального Chrome for Testing](https://googlechromelabs.github.io/chrome-for-testing/).

Из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, сохраните его настройки. Заполните:

```dotenv
OPENAI_API_KEY=ваш_ключ
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=-1000000000000
```

Создайте бота в BotFather, добавьте его в нужную группу и разрешите отправлять сообщения. В `TELEGRAM_CHAT_ID` нужен числовой ID группы, а не личный username. Для темы группы задайте `TELEGRAM_THREAD_ID`. ID можно получить из Telegram Bot API `getUpdates` после команды `/start@ИмяБота` в группе, если у бота не установлен webhook. Не публикуйте URL с токеном или содержимое `.env`.

`TELEGRAM_REQUIRED=true` по умолчанию: если доставка события не подтверждена, процесс останавливается до следующей отправки отклика. Для работы только с локальными логами задайте `TELEGRAM_REQUIRED=false` и оставьте оба Telegram-поля пустыми.

### 1. Вход в HH

```powershell
.\.venv\Scripts\python.exe -m hh_auto_apply --login-only
```

Войдите вручную **в открывшемся Chrome** как соискатель и нажмите Enter в терминале. Профиль сохраняется в `hh_auto_apply/user_data`. Следующие запуски используют его. Режим входа не требует LLM-ключа. Не открывайте один и тот же профиль в двух Chrome одновременно.

Проверка входа открывает личный раздел резюме (в новом интерфейсе HH он перенаправляет на `/applicant/profile/me`) и распознаёт меню аккаунта или содержимое личного профиля. После Enter скрипт ожидает загрузку страницы. Если старая версия сообщала «Не удалось подтвердить вход соискателя», сохранённая сессия при этом не удалялась: обновлённый скрипт может использовать её без повторного входа.

### 2. Тест: 5 писем в Telegram, без откликов

```powershell
.\.venv\Scripts\python.exe -m hh_auto_apply --dry-run --limit 5
```

Без аргументов запускается тот же режим. Скрипт читает вакансии, пропускает уже обработанные и видимые тесты, генерирует письма и отправляет логи в Telegram. **Форма отклика в этом режиме вообще не открывается.** Если тест/опросник виден только внутри формы, в тестовом режиме он останется неизвестен.

Лимит 5 означает пять подготовленных писем, а не первые пять карточек. Если подходящих вакансий недостаточно до `MAX_PAGES`/`MAX_SCANNED`, придёт `SHORTFALL` с количеством. Повторный тест допускается: черновики не блокируют будущие отклики.

Каждый запуск делает один проход. Когда выдача заканчивается, скрипт пишет причину завершения и закрывает Chrome. Лимит 100 не означает, что в поиске обязательно найдётся 100 новых вакансий; ожидание появления новых вакансий между проходами не включено.

### 3. Реальные отклики

Укажите `HH_RESUME_ID` — идентификатор нужного резюме из адреса `https://hh.kz/resume/<ID>`. Затем:

```powershell
.\.venv\Scripts\python.exe -m hh_auto_apply --apply --limit 5
```

Для проверки ровно одной выбранной вакансии:

```powershell
.\.venv\Scripts\python.exe -m hh_auto_apply --apply --limit 1 --vacancy-id 137845300
```

`--vacancy-id` ограничивает обработку указанным ID. Если вакансия пропущена или уже есть в истории, скрипт не переходит к другой.

Вакансия `137845300` уже получила ручной отклик с письмом и внесена в историю: повторный запуск с этим ID пропустит её.

Если HH открывает форму, скрипт выбирает резюме из `HH_RESUME_ID`, вставляет письмо и нажимает финальную кнопку. Дополнительные вопросы или тест в распознанной неотправленной форме приводят к пропуску. Если после перехода результат неясен, вакансия и письмо сохраняются для ручной проверки, повтор блокируется, а обход продолжается.

HH может создать отклик сразу при переходе на `/applicant/vacancy_response`, используя выбранное сайтом резюме. В таком сценарии скрипт открывает чат этой вакансии, проверяет ID в заголовке, нажимает «Добавить сопроводительное», вставляет письмо и отправляет его. Успех фиксируется после появления текста в переписке и исчезновения действия добавления письма. Выбор `HH_RESUME_ID` в этом сценарии не управляет резюме, уже выбранным HH; при нескольких резюме проверьте выбор на сайте перед запуском.

## Настройки

Все параметры описаны в `.env.example`. Основные:

| Параметр | Назначение |
|---|---|
| `HH_HOST`, `HH_QUERY`, `HH_QUERIES`, `HH_AREAS` | Сайт, одиночный запрос или список отдельных запросов, регионы через запятую |
| `HH_SALARY`, `HH_CURRENCY` | Необязательный жёсткий фильтр оплаты самого HH |
| `HH_EXTRA_PARAMS` | JSON дополнительных параметров из URL поиска HH |
| `HH_REQUIRED_WORDS`, `HH_EXCLUDE_WORDS` | Обязательные/исключающие подстроки через запятую |
| `DAILY_LIMIT` | 50 попыток отправки за календарный день по умолчанию |
| `RUN_LIMIT` | 50 попыток за запуск по умолчанию; подтверждённые и неизвестные считаются вместе; `--limit` может уменьшить |
| `MAX_PAGES`, `MAX_SCANNED` | Страниц на каждый запрос; уникальных карточек суммарно по всем запросам |
| `TIMEZONE` | `Asia/Qyzylorda`, для суточного лимита |
| `PAUSE_MIN`, `PAUSE_MAX` | Случайные паузы 5–12 секунд |
| `TYPING_DELAY` | Задержка между символами, 0 для вставки через `send_keys` |
| `LLM_MODEL` | Модель, доступная вашему API-аккаунту |
| `LLM_BASE_URL`, `LLM_API_MODE` | OpenAI Responses API или совместимый провайдер (`chat`) |
| `SELECTORS_FILE` | JSON с переопределением CSS-селекторов |

`HH_SALARY` оставлен пустым, чтобы посменную и месячную оплату сравнивать в отчёте. График и берег также не ограничивают поиск жёстко.

Паузы и скролл регулируют темп работы, но не гарантируют отсутствие ограничений HH. При распознанной CAPTCHA бот отправляет новое сообщение с упоминанием `@dokuzu` и просьбой решить её в открытом Chrome. Скрипт ждёт ручного решения **без ограничения времени**; во время ожидания не обновляет страницу, не повторяет отправку и не рассылает напоминания. После исчезновения CAPTCHA сообщение обновляется, обработка продолжается с текущего этапа. Время решения не расходует обычный тайм-аут ожидания страницы. Ожидание можно прервать через Ctrl+C. Если Telegram недоступен, уведомление останется в локальном логе, а ожидание продолжится. Ограничение доступа без CAPTCHA требует отдельной проверки. Обход CAPTCHA и маскировка Selenium не реализованы.

## Логи и восстановление

Для каждой вакансии Telegram получает одну обновляемую карточку: первый этап создаёт сообщение, следующие редактируют его через `editMessageText`. ID сохраняются в `telegram.sqlite3` отдельно для бота, группы и темы; повторный запуск обновляет ту же карточку. Общий статус запуска также обновляется в одном сообщении. Если текст не меняется, запрос в Telegram не выполняется.

Карточка содержит ссылку, условия, описание и готовое письмо. Между блоками — пустая строка; заглушки «Письмо ещё не составлено» нет. После подготовки письма или подтверждённого отклика обновляются счётчики текущего запуска в карточке и общем статусе: например, `Тестовые письма: 3/5 | Отклики HH: 0`.

Вакансии со статусом отклика на карточке HH или записью в истории пропускаются сразу: без открытия страницы, генерации письма, случайной паузы и отдельного редактирования Telegram-карточки. Каждый пропуск сохраняется в `skipped.log` и `events.jsonl`; в Telegram приходит одна сводка по таким пропускам в конце прохода. Паузы для работы с новыми вакансиями сохраняются. Итоговый статус явно указывает причину завершения: конец выдачи, лимит попыток, суточный лимит, предел страниц или просмотренных карточек.

В конце прохода Telegram получает новую короткую сводку и пронумерованные части отчёта. Подтверждённые отклики из всей сохранённой истории показываются списками до восьми ссылок в сообщении. Каждый неразобранный случай `unknown`/`pending` получает отдельное сообщение со ссылкой и полным письмом для ручной проверки. Перед ручной отправкой проверьте чат: отклик мог уже отправиться. В тестовом режиме добавляется список подготовленных писем текущего прохода. Ссылки упорядочены по графикам: 2/2, 5/2, остальные, неуказанный; каждая ссылка на отдельной строке. Отчёт не ограничивается последними 5–10 вакансиями. Файлы в Telegram не отправляются; локальная полная копия с описаниями и письмами — `last_report.txt`.

Полные длинные тексты разбиваются на части по лимиту Telegram; ID каждой части сохраняется, и она также редактируется. При сокращении текста лишние части удаляются. Если сообщение удалили вручную, создаётся замена; при других ошибках редактирования новые копии не рассылаются. У сообщений, отправленных старой версией до сохранения ID, нет связи с новыми карточками: они остаются в истории группы.

Запросы ограничены по темпу. При 429 скрипт ждёт указанное Telegram время; редактирование допускает повтор при временном сетевом сбое. При потере ответа на первоначальную отправку автоматического повтора нет, поскольку сообщение могло уже прийти. Без полученного ID перезапуск в таком редком случае может создать ещё одну карточку.

Локальные копии в `hh_auto_apply/runtime`:

- `app.log` — читаемый журнал;
- `skipped.log` — пропущенные вакансии;
- `events.jsonl` — структурированные события с описаниями и письмами;
- `state.sqlite3` — попытки отправки и тестовые черновики.
- `applied_vacancy_ids.txt` — ID подтверждённых отправленных откликов, по одному на строку.
- `telegram.sqlite3` — ID и последний текст Telegram-карточек.
- `last_vacancy_links.txt` — последний итоговый список ссылок по графикам.
- `unknown_applications.json` — отдельный список неразобранных `unknown`/`pending`: ID, ссылки, названия, даты и письма. Обновляется при фиксации результата и восстанавливается из БД при запуске.
- `unknown_applications.txt` — читаемый итоговый отчёт для ручной проверки.
- `last_report.txt` — полная локальная копия отчёта со всей сохранённой историей, описаниями и письмами; предыдущие копии остаются в `reports/`.

Запись попытки создаётся **до перехода на страницу отклика**, поскольку уже этот переход может отправить его. `sent` — отклик с письмом подтверждён HH; `pending` — процесс прервался; `unknown` — полный результат не подтверждён. Все три статуса блокируют повтор и учитываются в суточном лимите. Для явно распознанной формы, пропущенной до отправки, резерв снимается. Лимит касается попыток этого приложения в этой БД, а не ручных откликов или других компьютеров.

После подтверждения HH ID атомарно сохраняется в `applied_vacancy_ids.txt`. При запуске файл дополняется подтверждёнными откликами из БД, а ID, добавленные в файл вручную, сохраняются. Наличие ID в файле блокирует обработку даже без записи в БД. Тестовые письма, пропуски и неподтверждённые попытки в этот список не попадают; `pending`/`unknown` продолжают блокироваться через SQLite. Не удаляйте ни файл, ни БД: каждый из них защищает от повторов.

Неизвестный исход отдельной отправки больше не останавливает обход. В конце прохода Telegram получает пронумерованные сообщения со всеми неразобранными случаями, включая прошлые запуски, ссылками и полными письмами. Например, 97 подтверждённых и 3 неизвестных исхода исчерпывают лимит запуска 100. Эти же попытки учитываются в суточном лимите. Ctrl+C, недоступность обязательного Telegram вне ожидания CAPTCHA и поломка браузера по-прежнему останавливают работу; уже сохранённые случаи остаются в JSON и БД. После разрешения записи командой `history` JSON обновляется; следующий отчёт в Telegram будет сформирован с учётом исправлений.

Просмотреть историю:

```powershell
.\.venv\Scripts\python.exe -m hh_auto_apply.history
```

После ручной проверки раздела откликов HH разрешить неопределённую запись:

```powershell
# Если отклик есть:
.\.venv\Scripts\python.exe -m hh_auto_apply.history --resolve 123456 --outcome sent
# Только если проверено, что отклик НЕ отправлен, разблокировать повтор:
.\.venv\Scripts\python.exe -m hh_auto_apply.history --resolve 123456 --outcome not-sent
```

Команда работает только со статусами `pending`/`unknown` и блокируется во время основного запуска. Не удаляйте БД для обхода лимита: это сотрёт защиту от дублей.

Профиль Chrome содержит авторизацию; журналы содержат персональные письма. `.env`, профиль Chrome и runtime исключены из Git. Данные кандидата и описание вакансии передаются выбранному LLM, отчёты — в настроенную группу Telegram.

## Проверки и границы проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
# Настоящий Selenium на локальных тестовых формах:
$env:RUN_BROWSER_TESTS = '1'
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют отсутствие отправок в dry-run, выбор резюме, заполнение письма, пропуск опросников, лимиты, неизвестный исход, повторы Telegram, стиль и предпочтения. Локальные браузерные тесты не отправляют отклики на HH.

Проверки входа покрывают новый интерфейс HH, гостевую страницу, задержку загрузки, закрытие исходной вкладки и сохранённую сессию. Есть девять проверок в настоящем Chrome на локальных страницах. Проверки Telegram покрывают сохранение ID между запусками, редактирование частей, счётчики, удалённые сообщения и отсутствие повторной отправки при неопределённом сетевом исходе. В рабочей Telegram-группе проверены два редактирования одного служебного сообщения с тем же ID.

Публичная разметка выдачи и вакансии HH.kz была прочитана при разработке, карточки и ссылки также проверены в Selenium. Во время первоначальной проверки полного прохода по пяти вакансиям Chrome иногда получал пустую страницу поиска. Авторизация позже проверена на сохранённой сессии Наргиз.

Доставка в Telegram и реальные ответы LLM проверены с текущими настройками. В HH проверены ручной отклик `137845300` и автоматический отклик `136837403`. Во втором случае HH создал отклик при переходе по ссылке; после адаптации скрипт автоматически прикрепил подготовленное письмо через чат. Полный текст проверен после повторной загрузки чата. Обычная форма с выбором резюме покрыта локальными Selenium-тестами, её реальная отправка на HH ещё не проверена. Селекторы находятся отдельно в `selectors.py`. Автоматическая проверка письма контролирует формат и штампы, но не гарантирует фактологическую точность LLM — для проверки стиля и содержания предназначен первый тестовый запуск.

## Структура

```text
hh_auto_apply/
  config.py             # .env, поиск, лимиты
  user_profile.py       # факты кандидата и предпочтения
  prompt_templates.py   # универсальный промпт
  llm_service.py        # LLM и проверка текста
  browser_driver.py     # Chrome, сессия, ручной вход
  parser_applier.py     # выдача, вакансии, форма отклика
  selectors.py          # локаторы HH
  preferences.py        # мягкая оценка условий
  reports.py            # итоговые ссылки по графикам
  telegram_logger.py    # Telegram, файлы, JSONL
  state.py              # SQLite и защита от дублей
  history.py            # ручное разрешение unknown/pending
  runner.py             # общий цикл, dry-run и apply
  main.py               # CLI и жизненный цикл
  models.py
  user_data/
tests/
```

## Улучшения плана

Уже добавлены: отдельная история черновиков и откликов, выбор конкретного резюме, подтверждение результата HH, блокировка параллельных запусков, продолжение обхода с отдельным отчётом по неопределённым отправкам, мягкие предпочтения и смена LLM-провайдера.

Следующие полезные шаги:

1. Геокодирование адресов с проверенной границей берегов Астаны — для сортировки вакансий по месту работы.
2. Кнопки в Telegram «отправить / пропустить / исправить письмо» — если захочется проверять каждое письмо перед откликом.
3. Сохранение утверждённого письма из тестового режима для отправки без повторной генерации. Сейчас `--apply` генерирует новое письмо, поэтому оно может отличаться от тестового.
